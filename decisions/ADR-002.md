# ADR-002 — AWS Cost Optimisation

**Status:** 🟡 PROPOSED — Pending team confirmation of OI-1/OI-2 from ADR-001  
**Issue:** Derived from cost review (pre-Phase 4)  
**Created:** 2026-08-20  
**Authors:** Cost review across all PRD/implementation plan documents  
**Supersedes:** Portions of ADR-001 D12, D13, D14 (original draft values)  
**Does NOT change:** Core research methodology, PPO algorithm, MDP formulation, reward function, state/action space design, or experiment scope E1–E10.

---

## 1. Purpose

This record documents the structured cost review of every AWS service originally specified in `PRD.md` §12, carried out before Phase 4 work begins. The goal is to reduce unnecessary AWS expenditure without invalidating the DRL load-balancing research.

**Original estimated total:** $15–35 USD  
**Revised estimated total:** $5–15 USD  
**Research impact:** None — all core research objectives O1–O8 remain achievable.

---

## 2. Service-by-Service Classification

| Service | Classification | Cost Concern | Decision | Research Impact |
|---------|---------------|-------------|----------|-----------------|
| **EC2 t2.micro (backend × 4)** | ✅ KEEP — required | EC2 charges when running. 5 instances × continuous = ~$5/month. | KEEP, but stop all instances (ASG desired=0, min=0) between experiment sessions. | None — backends are the experiment subject. |
| **ALB** | ✅ KEEP — required | $0.0225/hr fixed, not free tier. ~$16/month if left running 24/7. | KEEP for experiments, but **delete between phases** (not just stop — ALB charges even when idle). Recreate before each experiment session via `src/aws/deploy.py`. | None — ALB weighted routing via `elbv2` is how PPO routing decisions are implemented on AWS. Replacing with Nginx would make the core AWS integration untestable. |
| **Lambda × 3** | ✅ KEEP — required | 1M free requests/month; well within budget. | KEEP. Reduce memory to 128 MB (was 512 MB in original spec). Duration < 3s per invocation. | None — Lambda state collector and scaling trigger are core to the feedback loop. |
| **CloudWatch (built-in metrics)** | ✅ KEEP — required | Always free (EC2 CPU, ALB metrics). | KEEP. | None — source of 4/5 state vector components. |
| **CloudWatch (custom metrics)** | ✅ KEEP — reduced | Originally ~20 custom metrics ($3/month beyond free tier of 10). | **Reduce to 8 custom metrics** (QueueDepth + ResponseTimeEMA × 4 instances). `active_conn` and `arrival_rate` derived from free ALB built-in metrics instead. Stays within 10-metric free tier. | Minimal — state vector composition unchanged; metric source changes from custom-published to ALB built-in for 2 of 5 per-instance features. |
| **CloudWatch Logs** | ✅ KEEP — reduced | Log retention cost. | Reduce log retention from 30 days to **7 days**. | None. |
| **S3** | ✅ KEEP — required | < 5 GB → free tier. | KEEP. | None — model storage and state buffer. |
| **DynamoDB** | ✅ KEEP — required | Free tier covers all project usage. | KEEP. | None — routing audit trail for reproducibility. |
| **ASG** | ✅ KEEP — required | No additional cost beyond EC2. | KEEP. | None — proactive scaling is tested in E7. |
| **IAM** | ✅ KEEP — required | Always free. | KEEP. | None. |
| **SNS** | ✅ KEEP — required | Free tier. | KEEP (1 topic for billing alarm). | None. |
| **SageMaker** | ⚠️ OPTIONAL — not primary | $0.046/hr; not free tier. | **Demote to last-resort fallback.** Primary training path: local laptop (~3–4 hrs) → Google Colab (free) → SageMaker only if both fail. | None — training location does not affect the trained model or experiments. |
| **API Gateway** | ❌ REMOVED from critical path | Consumes the 1M/month free tier unnecessarily; adds one network hop of latency that pollutes experiment measurements; provides no research value for load-balancing comparison. | **Remove from primary data flow.** JMeter targets ALB DNS directly. API Gateway may be added optionally if the team's account security policy requires it, but is not provisioned by default. | None — JMeter → ALB is functionally equivalent. The research question is about ALB routing behaviour, not API Gateway throughput. |
| **CloudFront** | ❌ REMOVED entirely | Dashboard CDN provides no research value. "Free tier" still has setup overhead, IAM config, and is one more resource to tear down. | **Remove entirely.** The Dash monitoring dashboard runs locally on the experimenter's laptop, reading from S3 every 5s. | None — monitoring dashboard is a convenience tool, not a research measurement. |
| **EC2 inference server** | ✅ KEEP — revised | 1 additional t2.micro. If all 5 t2.micro run simultaneously 24/7, exceeds 750 hr/month Free Tier. | KEEP architecture (EC2 server confirmed over Lambda due to SB3 size limit). Add strict **stop/start discipline**: inference EC2 stopped between sessions. | None — EC2 inference server is the only viable deployment approach given Lambda's 250 MB size limit. |

## 8. Revised Cost Estimate

| Scenario | Original | Revised |
|----------|---------|---------|
| Conservative (4 hrs active/day, 14 exp days) | $12–18 | **$4–8** |
| Realistic (6 hrs active/day, 14 exp days) | $20–30 | **$7–12** |
| Maximum (8 hrs active/day, 14 exp days) | $35–45 | **$10–15** |

**Primary cost drivers remaining:**
1. **ALB** — $0.0225/hr fixed + LCU charges during active experiments (~$1.30 fixed + ~$0.50 LCU estimated)
2. **EC2** — 5 t2.micro during experiment sessions (~$2–5 depending on hours used)

> This design aims to minimise AWS expenditure and stay within available Free Tier and student credits where possible. It does not guarantee a zero-cost experiment campaign. ALB and EC2 will incur charges during active experiment windows.
