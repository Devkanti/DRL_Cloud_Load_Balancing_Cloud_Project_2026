### D3 — Rejected Algorithms (DDPG and H-MAS)

<<<<<<< HEAD
**Decision:** DDPG and H-MAS are **NOT implemented** as primary algorithms. Retained as related-work discussion only.

**DDPG rejection:** Continuous action space mismatch; hyperparameter instability; no evidence of advantage over PPO for burst-traffic routing (PRD §10.3).

**H-MAS rejection:** Doubles implementation complexity; key benefit (noise filtering) is preserved via the `burst_indicator` state feature (PRD §10.4).

**Status:** ✅ Locked.
=======
**Decision:** DDPG and H-MAS are **NOT implemented** as primary algorithms. They are retained only as related-work discussion.

**DDPG rejection rationale (from PRD §10.3):**
1. Our ALB routing is inherently discrete; DDPG requires continuous actions, adding unnecessary continuous-to-discrete mapping complexity.
2. DDPG is hyperparameter-sensitive and slower to converge — an unacceptable risk for a student-budget project.
3. No surveyed paper demonstrates DDPG outperforming PPO for request-level routing under burst traffic.

**H-MAS rejection rationale (from PRD §10.4):**
1. H-MAS requires designing and coordinating multiple agents — doubles implementation complexity for uncertain benefit.
2. The key H-MAS noise-filtering benefit is preserved via the `burst_indicator` feature in the state space.
3. No empirical evidence from the surveyed papers supports H-MAS for flash-sale routing specifically.

**Mohar's contribution preserved via:**  
The `burst_indicator` state feature (`arrival_rate / λ_baseline > 2 → 1`) is a direct, simplified proxy for the noise-filtering role of the H-MAS supervisor layer. Mohar's H-MAS insight is thus architecturally embedded, not discarded.

**Status:** ✅ Locked — no changes permitted without raising a new ADR.

### D21 — Statistical Analysis Protocol
