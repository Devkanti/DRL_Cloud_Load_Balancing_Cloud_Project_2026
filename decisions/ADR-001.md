## Decisions

---

### D1 ΓÇö Primary DRL Algorithm

**Decision:** **PPO (Proximal Policy Optimization)** via Stable-Baselines3 v2.3.0.

**Rationale (from PRD ┬º10.1):**
- PPO's clipped surrogate objective (`╬╡=0.2`) prevents policy collapse under high reward variance ΓÇö a critical property for flash-sale traffic where reward signals swing dramatically between phases.
- Two of the five surveyed papers (Funika et al. 2023, Femminella & Reali 2024) validate PPO for cloud-related tasks.
- PPO supports parallel vectorised training (`VecEnv`).
- PPO works with both discrete and continuous action spaces; our routing problem is naturally discrete.

**Status:** Γ£à Locked.

---

### D2 ΓÇö Primary DRL Baseline

**Decision:** **DQN (Deep Q-Network)** ΓÇö Mnih et al. (2015), Stable-Baselines3 implementation.

**Architecture:** Identical 2-layer MLP [64, 64] to PPO. Experience replay buffer 100,000. Target network updated every 1,000 steps.

**Rationale (from PRD ┬º10.2):** Agrima's Phase-I document explicitly proposes DQN vs PPO as its core novelty. Closes Research Gap G3 (only prior comparison is in SDN simulation, not AWS).

**Status:** Γ£à Locked.

---

### D3 ΓÇö Rejected Algorithms (DDPG and H-MAS)

**Decision:** DDPG and H-MAS are **NOT implemented** as primary algorithms. Retained as related-work discussion only.

**DDPG rejection:** Continuous action space mismatch; hyperparameter instability; no evidence of advantage over PPO for burst-traffic routing (PRD ┬º10.3).

**H-MAS rejection:** Doubles implementation complexity; key benefit (noise filtering) is preserved via the `burst_indicator` state feature (PRD ┬º10.4).

**Mohar's contribution preserved via:** `burst_indicator` state feature ΓÇö direct proxy for H-MAS supervisor layer noise filtering.

**Status:** Γ£à Locked.

---

### D4 ΓÇö MDP Action Space

**Decision:** **Discrete action space A = {0, 1, 2, 3}** ΓÇö select one of N=4 backend EC2 instances as the routing target for the current 100 ms time window.

**N is configurable** in `FlashSaleEnv(n_instances=N)` and `configs/ppo_config.yaml`. Locked value for experiments: N=4.

**Cross-reference:** PRD ┬º9.3.

**Status:** Γ£à Locked.

---

### D5 ΓÇö MDP State Space

**Decision:** **23-dimensional state vector** `s_t Γêê Γä¥^23` for N=4 instances (formula: 5N+3).

```
s_t = [
  cpu_util[0..3],           # CloudWatch CPUUtilization, normalised 0ΓÇô1        (4 dims)
  active_conn[0..3],        # ALB ActiveConnectionCount (built-in), 0ΓÇô1        (4 dims)
  queue_depth[0..3],        # Custom FlashBalanceAI/Instances QueueDepth       (4 dims)
  resp_time_ema[0..3],      # ALB TargetResponseTime EMA, normalised 0ΓÇô1       (4 dims)
  health_status[0..3],      # ALB health check: 1=healthy, 0=unhealthy         (4 dims)
  arrival_rate_norm,        # ALB RequestCount / baseline, range [0, 10+]      (1 dim)
  burst_indicator,          # 1 if arrival_rate_norm > 2, else 0               (1 dim)
  time_since_last_spike     # Normalised seconds since last burst onset, 0ΓÇô1   (1 dim)
]
```

> **Note (updated per cost review):** `active_conn` and `arrival_rate_norm` are now derived from free ALB built-in metrics (`ActiveConnectionCount`, `RequestCount`) rather than custom CloudWatch metrics. This reduces custom metric count from ~20 to 8.

**Cross-reference:** PRD ┬º9.2, PRD ┬º12.2.

**Status:** Γ£à Locked.

### D6 ΓÇö Reward Function Weights

**Decision (provisional):**

```
R(t) = 0.4 ┬╖ R_lat(t) + 0.2 ┬╖ R_util(t) + 0.2 ┬╖ R_tput(t) + 0.2 ┬╖ R_sla(t)
```

| Component | Weight | Formula | Rationale |
|-----------|--------|---------|-----------|
| R_lat | wΓéü = 0.40 | `ΓêÆ(avg_resp_time / 200ms) + 1` | Primary user-facing SLA metric |
| R_util | wΓéé = 0.20 | `avg_cpu ΓêÆ |avg_cpu ΓêÆ 0.70|` | Penalises both under- and over-utilisation |
| R_tput | wΓéâ = 0.20 | `requests_served / requests_arrived` | Ensures requests are served, not just routed |
| R_sla | wΓéä = 0.20 | `ΓêÆ2.0 ┬╖ I(P95_latency > 500ms)` | Hard guardrail on tail latency |

**ΓÜá∩╕Å PROVISIONAL:** These are starting values. Experiment E10 will vary weights. Do NOT treat as "proven optimal".

**Cross-reference:** PRD ┬º9.4.

**Status:** ΓÜá∩╕Å Provisional.

### D14 ΓÇö PPO Inference Deployment Approach

**Decision (confirmed 2026-08-20 per cost review ΓÇö see ADR-002):** **EC2 t2.micro inference server** running `src/aws/inference_server.py` (Flask, port 6000). A lightweight Lambda coordinator (`inference_coordinator.py`, < 5 MB, no SB3) calls the inference server every 60s (EventBridge minimum rate), updates ALB target weights, and logs to DynamoDB.

**Why not Lambda for inference:** SB3 + PyTorch unzipped Γëê 300 MB, exceeding the 250 MB Lambda unzipped package size limit.

**Cost implication:** The inference t2.micro counts toward the 750 hr/month Free Tier. When stopped between sessions, it adds negligible cost.

**Cross-reference:** PRD ┬º12.2, IMPLEMENTATION_PLAN_PART2.md T5.2.

**Status:** Γ£à Confirmed (D14 open item resolved).
